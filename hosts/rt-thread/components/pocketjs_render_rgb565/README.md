# RT-Thread RGB565 renderer

The Rust binding adapts the existing `engine/backends/rgb565` renderer to the
RT-Thread allocator. It derives from the ESP-IDF binding and consumes the same
ABI generated by `tools/esp-idf-contracts.ts`. No engine platform conditionals.

One calling thread owns the UI, renderer and target. Prepare a damage plan, render
strips into caller-owned memory, present those pixels, then commit. Abort or
invalidate the target after a failed presentation. Frames expire at UI mutation,
tick, or draw; never access a frame after destroying its UI owner.

The component creates no thread, framebuffer or display driver. The D13x smoke
application owns those resources. With a null accelerator the renderer uses CPU
rendering. GE callbacks and tear-free buffer swapping are not implemented here.

Host contract check from the PocketJS root:

```powershell
$env:CARGO_TARGET_DIR = "$PWD/.pocket-build/host-render"
cargo test --manifest-path hosts/rt-thread/native/render-rgb565/Cargo.toml --lib
node --experimental-strip-types tools/esp-idf-contracts.ts --check
```

The test uses the real retained UI core. It checks every pixel in four color bars,
short-buffer rejection, untouched canaries, damage after commit/abort and stale
frame rejection. Board probes also compare allocation counters before/after.
